# Висновки

Відносно спільної бази 8.042206 с `@njit` дав приблизно ×41.7 (0.1927 с), а 32 процеси — ×5.13 (1.568056 с).
Numba компілює гарячий цикл, тому Python не виконує кожну його ітерацію через інтерпретатор.
NumPy дав лише ×1.23 (6.5286 с), бо формули обчислюються для всього масиву, навіть для завершених точок, і створюються тимчасові масиви.
П'ять розбіжних точок NumPy можуть пояснюватися округленням координат у `linspace`; у Numba збережено формули Python і перевірка показала точний збіг.
`prange` скоротив час до 0.0187 с і за виводом програми додав ×10.33 до `@njit`, виконуючи незалежні рядки паралельно.
Як і процеси, він використовує кілька ядер, але прискорення відрізняється через різний спосіб виконання й передачі даних.
Для такого коду я спочатку скомпілював би гарячий цикл, а потім додавав паралельне виконання.
