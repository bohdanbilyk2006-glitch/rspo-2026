## Де була помилка

Гонка даних виникала під час одночасної роботи кількох процесів зі спільними значеннями:

```python
if zalyshok.value >= kilkist:
    zalyshok.value = zalyshok.value - kilkist
    vidvantazheno.value = vidvantazheno.value + kilkist
else:
    vidmov.value = vidmov.value + 1
```

Операції читання і запису не виконувались як одна неподільна дія. Через це процеси могли перезаписувати результати один одного.

## Критична секція

Критична секція — перевірка залишку та зміна `zalyshok`, `vidvantazheno` і `vidmov`.

## Виправлення

Для критичної секції використано спільний `multiprocessing.Lock`.

Замок поставлено тільки навколо роботи зі спільними даними, а не навколо всієї функції.

## Результат

До виправлення: **0 із 5** прогонів без порушень.

Після виправлення: **10 із 10** прогонів без порушень.

В усіх виправлених прогонах:
- залишок = 0;
- відвантажено = 30000;
- відвантажено + залишок = 30000.

## Чому помилка не завжди видима

Результат залежить від порядку виконання процесів. Якщо два процеси одночасно читають старе значення і потім записують нове, частина змін губиться.

Тут використовуються процеси зі спільною пам'яттю, тому гонка проявляється стабільніше, ніж у потоковому варіанті.

## Час

До виправлення середній час: **0.6437 с**.

Після виправлення середній час: **0.5324 с**.

У цій серії виправлена версія була приблизно на **17.3% швидшою**.
